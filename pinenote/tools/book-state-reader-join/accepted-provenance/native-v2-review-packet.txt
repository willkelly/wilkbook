ACTUAL LOST-ACK EXECUTION
=========================

The loss book receives its generated Unicode edit only as an ordinary trusted
host action and submits the ordinary typed state-commit over its Book Session
socket.  The test-only factory's RUN-OPERATION wrapper calls the exact accepted
run-state-backend-operation.  After it returns a real receipt, the wrapper holds
a condition-variable baton before returning to the delegate worker.

While held, an asynchronous accepted close-session! call invalidates/detaches
under the endpoint mutex, shuts down the socket, revokes without that mutex, and
waits to join the worker.  Before releasing the baton, the test proves:

  adapter returned a real result:             yes
  endpoint state:                             closed
  queued outbound frames:                     0
  book read after commit:                     EOF
  book parsed state-committed:                 no
  exact book process group alive:             no
  independent read-only SQLite state:         version 1, exact generated text
  independent SQLite receipt:                 one, expected 0 -> resulting 1

Only after that evidence is published does the Python oracle release the baton;
close joins the worker and the already-closed endpoint is removed from the host.

A fresh authority and fresh Guile book then receive only the operation ID.  The
book loads the exact text via state-value and submits that text, operation ID,
and expected version 0 through Book Session.  It consumes the original
state-committed (version 1 and exact UTF-8 byte count), rereads current version
1, and presents the exact receipt summary.  A second SQLite comparison proves
value/version/one-receipt count unchanged.  Recovery text is absent from retry
argv/environment.

A third fresh authority/book executes the semantic counterexample: it consumes
the real state-committed and prints a pretend-loss marker.  Storage/protocol
replay succeeds, but validate_lost_ack_evidence rejects the loss claim because
the receipt was consumed.  SQLite remains unchanged.

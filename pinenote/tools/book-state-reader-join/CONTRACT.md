# Native persistent-note reader join contract

This directory joins three already-accepted boundaries without modifying their
frozen sources:

1. native-v2 Book State protocol, adapter, SQLite backend, and Book Session
   inputs;
2. completion-observer v1; and
3. the KOReader persistent-note UI packet.

The join-local `empty-action-successor/` is separately identified candidate
source: one exact patch over accepted completion-observer candidate `0342e87c…`.
It adds only a trusted state-text endpoint constructor. It is not presented as
part of the prior acceptance. The join is host-only and deliberately narrow:
one fixed note namespace per trusted language/profile and one private UI
interaction at a time.

## Authority and success order

Only this order may paint **Saved**:

```text
accepted UI Save callback -> submit
trusted host-action!("save-note", exact submitted text)
fixed book -> state-commit chosen operation ID
accepted delegate/adapter -> SQLite
typed endpoint-owned completion observer
exact pending-action/completion validation -> commit-ok
accepted UI -> Saved paint
fixed book receives a separate present-saved action -> present
accepted UI -> present / inherited paint / applied
```

`present` and `applied` are surface facts, never storage evidence. The outer
authority cannot call the backend to impersonate a book request. All reads and
commits originate as Book State messages on the book's Book Session socket.

The trusted pending record keeps UI generation, session ID, surface handle and
generation, grant generation, request ID, fixed action ID, action sequence,
derived book operation ID, expected state version, and an owned exact text copy.
The observer completion must match its session/surface/grant, operation kind and
ID, expected version, exact text, and typed response. Equal-looking generation
integers are retained as distinct fields and never treated as interchangeable.

The fixed books derive IDs as
`note_<CSPRNG-SURFACE-HANDLE>_s<SURFACE-GENERATION>_q<SEQUENCE>`. The fresh
surface handle is generated by the trusted Book Session host and arrives in the
book's initialize envelope. The resulting ID is ASCII and at most 128 bytes.
Neither UI nor outer test runner supplies it, and namespace authorization stays
in the endpoint grant rather than being encoded in the ID. A new Save intent
gets a new action and ID even if its text happens to match an earlier intent.
An actual retry of one already-created commit retains the original ID, expected
version, and exact text; the suite proves that the accepted backend returns the
original receipt without adding a row or incrementing state.

This finite join does not add a persisted UI operation journal. A future client
recovering a lost acknowledgement across restart must retain the original
operation identity; native-v2's lower-level lost-ack retry remains the accepted
proof of that mechanism.

## Process and data authority

- The Guile authority receives trusted root/profile/test-plan paths. It fixes
  profile to book revision, instance ID, backend access, and exact book source.
- A fixed Guile or Python book receives no application argv and only its
  factory-created connected Unix stream as FD 3. It receives no database path,
  namespace, profile, state value, expected result, or store object through argv
  or environment.
- KOReader receives its inert document argv and only the accepted private UI
  control stream as FD 3. It receives no expected state or result through argv
  or environment.
- The Python test oracle never brokers either channel. It may inspect retained
  SQLite only after each authority, book, and KOReader process has terminated.

Every authority records fresh `(PID, /proc start-time)` identities for itself,
its book, and KOReader. Endpoint release revokes the session/grant before UI
finish. Processes are terminated only when the recorded start time still
matches, logs and protocol queues are bounded, and each phase has a finite
deadline. A durable commit is not promised cancellable: reopen/read and exact
retry are the recovery mechanism.

## State-text endpoint policy

The accepted constructors keep their nonempty action rule and 2,048-byte action
limit. Only
`make-book-session-host-with-state-text-observer` opts an endpoint into the
Book State text range: 0 through 4,096 UTF-8 bytes for trusted host actions and
matching book presentations. The policy is selected at trusted construction;
no peer field, action ID, caller-provided limit, or wire-schema change can
enable it. The accepted state protocol, delegate, adapter, backend, observer,
and UI sources remain byte-for-byte unchanged. Ordinary UI NUL exclusion also
remains unchanged.

## Fixed executable scenarios

The bounded suite uses 22 fresh Guile-authority/book/KOReader lifecycles:

- multilingual Guile save A, fresh load/edit/save B, fresh load/edit/save C,
  and fresh observer-driven reopen, advancing versions 1 → 2 → 3;
- the same restart/save/reopen sequence for Python under `-I -S`;
- absent read, actual UI nonempty Save, fresh UI Clear → Save of empty text,
  then fresh present-empty read/UI paint;
- a seeded read-only note followed by two real backend failures with the same
  retained empty widget draft, leaving durable state/version unchanged;
- an exact 4,096-byte UI Save and fresh reopen;
- an explicit same-operation retry returning one original receipt and one
  version increment;
- an actual edit of the live `InputDialog` while a matching receipt is withheld:
  the older commit is durable but the newer widget draft remains Dirty;
- forged early book presentation, with no completion and no Saved paint;
- a real book commit of text different from the pending UI draft, rejected as
  UI evidence, followed by fresh read recovery of the durable value.

Present-empty is now produced by the real accepted UI Save callback, a trusted
empty host action, a book-issued empty commit, SQLite receipt, typed completion,
correlated `commit-ok`, Saved paint, and separate empty book presentation. It is
not inferred from `present` or `applied`. The accepted UI's NUL exclusion is
unchanged; this join makes no NUL-rendering claim and does not reinterpret
native-v2's separate 4,096-byte NUL proof.
